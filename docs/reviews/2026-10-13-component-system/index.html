What changed

AreaShared treatment
ActionsButton variants, consistent focus and disabled states, 48-pixel ordinary action targets. Custom surfaces use a native-compatible button wrapper.
PreferencesSelected immediate on/off preferences use switches. Selection and consent keep native checkboxes. Segmented and illustrated choices retain their established forms.
FieldsShared input, select and textarea primitives; a label/help/error wrapper used in the updater and available for new forms.
Feedback & detailsShared status paragraphs and native disclosures, with atomic announcements and keyboard-visible focus.
Design rulesControl sizes, focus, spacing and disabled treatment use one stylesheet and existing palette roles. The live showcase exercises the actual components.

Verification and boundaries

TypeScript passes. 86 JavaScript and 19 Python tests pass. The Settings suite passes 13 workflow groups and captures 62 views without runtime errors. Top-level screen checks cover eight screens at three landscape sizes, photo browse/zoom and persistent exclusion. Component checks cover switches, selection, feedback, field errors, disabled state, segmented keyboard operation and light/dark overflow at 1280, 1920 and 390 CSS-pixel widths.

Settings lightbox lifecycle, task navigation, staged editing and some dynamically generated controls remain in existing controllers. SettingRow is demonstrated in the showcase; feature-specific product row layouts remain. The phone page uses shared React primitives with its existing compact stylesheet. This is a consolidated control library, not a replacement of every layout/controller or a new dashboard-editor design.

The signed 2.17.0 APK has been rebuilt. These changes have not been installed on the frame or merged. Physical WebView/touch acceptance remains outstanding. The showcase is excluded from the APK.
